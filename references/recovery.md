# 补同步与失败恢复

补同步是对明确来源 ID 的修复，保持原始身份；不能把一次授权扩展为全量迁移、同步他人任务或新建新来源对象。

## 决定是否需要创建

1. 读取来源现状和历史、当前同步策略。本人报告而未被分配的缺陷，不擅自设经办人为本人；需要业务归属或策略选择时向用户说明具体缺失信息。
2. 按完整来源唯一键查 Base。0 行可进入补录判断；1 行读取 Linear ID/创建标记/状态；多行先核对，不能任选第一行或删除重复行。
3. 有 Linear ID 时只查询该 Issue。查询失败不能当作不存在；权限不足或目标不可见时停止创建。仅当产品明确证实 Issue 已删除、且用户选择重建时才更换映射。
4. 无 Linear ID 时按来源 URL/唯一键、来源 ID 和时间查 Linear，精确核对；标题搜索只作候选，不可仅凭同名或搜索为空认定有/无 Issue。
5. 能定位唯一已有 Issue：回填其 ID/URL，核对 Team/负责人后更新。多候选或证据不足：待核对，停止自动创建。
6. 确认未创建、来源符合策略且用户授权补录：使用原空间/类型/来源 ID 补录或补发一次；不要创建新的飞书任务以“触发同步”。

## 创建标记的恢复

- 创建已尝试 + ID 为空：先查 Linear。不能只把状态改待同步，模板会再次拦截；也不能直接清除标记以绕过去重。
- 确认存在：回填 ID/URL；核对来源当前标题/状态和时间水位，再按需要触发更新。
- 可靠确认不存在后才清除已尝试、设置待同步并进行**一次**受控重试。请求未确认时停止，读取两侧结果；不能无限重放。
- HTTP 明确拒绝与网络超时可能对应不同创建结果，但仍检查业务响应；若 schema 无法读取错误分支字段，不能自行推断成功或失败。
- 若只能通过修改现有来源标题引发事件，不要加空格、改成 test 等改变真实业务内容；使用可授权的补录/回放路径，或说明缺少恢复入口。

## 负责人变化与迟到事件

参考模板对涉及负责人变化的已入表任务暂停。恢复前用源端当前负责人证明仍符合策略，再人工恢复有效标记和所需状态。创建时不属于本人、后来才转入的任务没有映射，必须单独确认支持转入/补录；不能借助测试消息绕过创建筛选。

删除映射保持 tombstone。后续改名/状态事件不应复活；如果来源真的恢复，读取最新事实、确认恢复策略后再处理。

## 授权和验收

授权搭建同步不自动允许批量重放、公开未保护端点、放宽所有者条件或永久删除业务数据。按实际工具要求处理确认；用户已经明确授权的同一动作不反复询问。

单条补同步后验证：原来源 ID、映射只有一行、Linear 只有目标 Issue、ID 回写、正确账号/Team/状态。记录本次是新建、回填还是更新，报告实际结果与剩余阻断。只说请求发送成功不算恢复完成。
